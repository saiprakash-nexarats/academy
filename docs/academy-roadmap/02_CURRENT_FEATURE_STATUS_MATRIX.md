## 2. Mock Dependency Summary

Every single state-mutating action in the application currently terminates in one of four mock mechanisms:
1. **Local Boolean State Toggle:** `setSubmitted(true)`, `setLoggedIn(true)`, `setBookingSubmitted(true)`, `setBookingConfirmed(true)`. Refreshing the browser instantly erases all state.
2. **`console.log()` Output:** Form data in `EnrollModal` is only outputted to the developer browser console via `console.log('Enrollment Inquiry Submitted:', data)`.
3. **Simulated Delays:** `await new Promise((resolve) => setTimeout(resolve, 800))` creates an artificial network delay without making any HTTP request.
4. **Browser Alerts:** `alert('Certificate link copied to clipboard!')` provides browser-level placeholder feedback.

## 3. Production Readiness Criteria

To bring this feature set to production-grade enterprise readiness, every row in the matrix must fulfill the following 5 requirements:
1. **Network Integration:** Replace local state swaps with strongly typed TanStack Query / Axios API calls communicating with the backend.
2. **Persistence & Auditing:** Every submitted form must write to a PostgreSQL entity with full audit trail logging (`created_at`, `created_by_ip`, `tenant_id`).
3. **Role-Based Redirection:** Successful authentication must redirect users to their authorized portal based on RBAC attributes (e.g. `/portal/student`, `/portal/mentor`, `/portal/admin`, `/portal/corporate`).
4. **Resilience & Feedback:** User-facing notifications must use an accessible toast library with explicit error handling for 400 Bad Request, 401 Unauthorized, 403 Forbidden, 429 Rate Limited, and 500 Server Error responses.
5. **Security & Token Handling:** Auth credentials must be exchanged for short-lived access tokens and secure, HttpOnly, SameSite refresh tokens with rotating refresh tokens.
